# 題目卷審題版

完整段考另交付一份 B4 直式雙欄的「題目卷（審題版）」，逐題依序呈現三部分：

1. **本次題目**：完整題幹、選項、共用情境、小題及必要配圖，與正式題目資料一致。
2. **來源與原題**：標明課本／習作／網路；教材列檔名、印刷頁碼、PDF頁碼、題號（含小題），網路列標題、網址及題號／講稿段落；附原題或原始示例的完整必要條件。表格指定格、圖片條件轉文字、概念段落整理及非逐字轉錄都要明說。
3. **重點分類**：單元、唯一主重點、Bloom認知層次及配分。沿用全卷規劃的分類，不另分教材與網路兩套權重。

網路題候選另附官方學習內容／學習表現代碼、PDF頁碼及備註限制核對，保留獨立 `curriculum_review.json`；正式匯出審題版也須提供 `--curriculum-report`。規格見 [來源規劃](source-planning.md)。

不把能力點綜合原創題虛稱為某道原題直接改編。原創題保留真正命題依據，回查精確教材對照題時明列「後補教材對照，非原先直接改編題」。概念頁沒有題號就寫「概念說明，無題號」，不可補造。網路觀念原創也與直接改編分開標示。

來源必須實際回查；網路原題可整理其數值、條件與關係並附連結，避免整份搬運題庫。原文、整理內容及命題者補述必須區分。未取得的來源或未查證頁碼須先補齊，不能用猜測完成來源紀錄。

## 獨立來源資料

將原題紀錄放在當次考卷的 `命題資料/review_sources.json`，與定稿JSON並列；場次資料夾見 [命題範本](exam-template.md)。不必改動已批准的考卷JSON。最外層包含 `schema_version: 1`、`exam_sha256`（以 `exam_validation.exam_digest(data)` 計算）及 `questions`。
`questions` 的鍵為 `mc_1`、`fill_1`、`open_1_1` 等所有實際作答單位，不可缺漏或多列。

每題內容格式：

```json
{
  "relationship": "concept_original",
  "sources": [{
    "kind": "workbook",
    "title": "使用者實際提供的習作檔名",
    "locator": "印刷第55頁；PDF第2頁；基礎練習第3題的指定欄位",
    "original": "實際回查後填入原題；數學以 {3*x-1} 標記",
    "transcription": "原題表格指定欄位轉錄"
  }]
}
```

此段僅示範欄位，不代表真實教材定位，須依當次檔案填寫。
`relationship`：`direct_adaptation` 直接改編、`concept_original` 教材能力點綜合原創、`concept_reference` 網路觀念原創。
`kind`：`textbook` 課本、`workbook` 習作、`web` 網路；網路必須另填 `url`。
題目變更後來源摘要會失效，須重查並更新，不能只機械替換摘要。

## 匯出

一般完整匯出加上 `--question-review-sources` 並指向當次 `命題資料/review_sources.json`，會在當次 `Word/` 額外產出第五份文件。
只補出審題版時再加 `--question-review-only`；仍須提供有效 `--math-report` 及必要 `--figures-dir`。
這份文件與既有 A4 的 Bloom「審題報告」用途不同，不互相取代。
正式交付前實際渲染逐頁確認三部分、公式、選項、配圖與雙欄順序，盡量不拆散同一道題目。
