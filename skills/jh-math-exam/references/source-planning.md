# 章內重點配分與來源審閱

## 命題前規劃

依使用者教材列出章內能力點（如係數、代入、分配律、去分母、年齡、速率），列明PDF頁碼、
目標分數、題型、認知層次、規劃理由及排除項目。依教學比重配置，不強迫每個小重點等分。
每個作答單位指定一個主重點 `primary_topic`；次要能力可以備註，但不可重複累加配分。
出完逐項核對題號、實際分數、來源比例與漏考項目，不能只看三節總分接近。
教材題與網路題須合併在同一份全卷重點配分表中規劃與驗收，不能各自分配比例後才拼成考卷。
80／20是來源限制，不是兩套能力配分。先固定全卷各主重點的分數，再決定各題從哪種來源取材。
補入或替換任何網路題後，重新計算整卷的主重點、題型與認知層次，來源達80／20但重點失衡仍不可匯出。

## 教材80%、網路20%

預設按全卷配分計算；100分即80分教材、20分網路。25題各4分時為20題教材、5題網路。
24題配置含4題各5分計算題時可將4道計算題作為網路題，也可選其他精確20分的組合。
不能精確達標時，先提出可行配置；未取得教材時保留缺口，不能把模型自行命題標成已讀教材改編。

教材題依實際題型與條件改編，保留檔名、PDF頁碼和改編方式；可以綜合教材能力點原創，但須明說，
不可聲稱每題均有對應原題。網路來源須實際開啟閱讀，優先教育機關、學校、基金會等公開資源。
區分「原題改編」與「參考觀念後原創」，記錄網址、標題、頁碼／題號／段落、讀取日期與改編說明。
僅有搜尋摘要、未讀取的影片或登入後題目，不能宣稱已核對原題。可改選可讀來源或據已讀觀念命題並說明限制。
兩類題都重新設計數值，核對提供教材與習作，不照抄原題完整條件。不要整份搬運網路題庫。

## 網路題先審後用

先交付候選清單：完整題幹、四選項（選擇題）、答案與解析、來源連結、能力點、配分、
預計替換位置與改編差異。使用者明確同意後才記錄審閱；尚未同意可留待審稿，不能納入正式匯出。
`approval` 只由實際使用者回覆建立，不得自動填 approved；題幹、選項、答案、解析或共用情境修改後須重新審閱。

## 網路題官方課綱核對

網路題另須符合 [官方國中課綱](national-math-curriculum.md) 的學習內容、學習表現及**備註限制**，
並在本次已教章節與解法內。不得只因題庫標示「國中」、來源為學校網站、或使用者已同意就視為合格。
逐題核對完整題幹、全部選項、解析步驟及必要先備知識；官方排除題型、尚未教的能力或高中方法均須排除。
例如N-7-5不處理絕對值方程式／不等式，F-9-2不能把高中二次函數配方法及應用問題直接納入國中範圍。

候選清單同時附官方代碼、PDF頁碼、備註與範圍核對理由，取得使用者同意後仍須完成此獨立核對。
超綱原題先改編成範圍內的新題，重新驗算並送審；不能改編就排除，不能用原題標籤補湊20%。
改題後重算整卷主重點分布，不能為來源比例破壞全卷規劃。

每份考卷在當次場次資料夾的 `命題資料/curriculum_review.json` 記錄（場次結構見 [命題範本](exam-template.md)）：

- 最外層：`schema_version:1`、`exam_sha256`（`exam_digest(data)`）、`official_pdf_sha256`（`official_curriculum_index()[0]`）、`checks`陣列。
- 每個網路作答單位一列：`id`、`content_codes`、`performance_codes`、`official_pdf_pages`。
- 實際完成後才記錄布林值 `compliant`、`in_scope`、`remarks_checked`、`methods_in_scope`；任一未通過即禁止正式匯出。
- 必填文字理由：`scope_note`（本次教材章節與已教能力）、`remarks_note`（官方備註核對結果）、`method_note`（完整解法為何在範圍內）。不能循環填True冒充核對。

代碼與PDF頁碼取自已讀官方條文；沒有備註的條目明說備註欄無文字，仍須核對題目和解法。
正式匯出有網路題時必須提供 `--curriculum-report`；缺紀錄、漏題、無效代碼／頁碼、不符課綱或題目／PDF版本已變更即停止。
`--validate-only`／`--blueprint-only`可保留待核對警告，不能因此宣稱通過正式驗收。
課綱核對與使用者同意各自成立，不能互相替代；程式只驗證紀錄完整性與版本，不會自動證明語意符合課綱。

## JSON 欄位

下列欄位加入考卷最外層；正式匯出必須同時提供，缺少規劃不得回退到無來源的舊流程：

```json
"source_policy": {"basis":"points", "material_percent":80, "web_percent":20},
"content_plan": [
  {"id":"T1", "section":"3-1 代數式的化簡", "name":"係數與常數項", "target_points":8,
   "rationale":"基本概念以兩題檢查"}
]
```

`content_plan` 須列全卷所有主重點，`target_points` 合計全卷分數。每題或計算子題加：

```json
"primary_topic":"T1",
"provenance": {"kind":"material", "file":"教材.pdf", "locator":"PDF第3頁例1",
  "adaptation":"依係數概念原創；改數值與選項"}
```

網路題的 `provenance` 改用 `kind:web`、`url`、`title`、`locator`、`accessed`、`adaptation`，
初始 `approval:{"status":"pending"}`。收到同意後，使用
`source_question_digest(exam, "mc_3")` 計算本題摘要，記錄為
`approval:{"status":"approved", "question_sha256":"摘要", "user_confirmation":"使用者實際回覆"}`。
雜湊僅用來阻止沿用舊審閱紀錄，不代表程式能判斷回覆真實性；執行者須如實記錄。

匯出器檢查每個主重點配分、章節一致性、來源比例及網路審閱版本。
`--validate-only` 可檢查待審稿並列待審警告；正式匯出遇待審題直接停止，
不能以驗算通過或模型自審取代使用者審閱。來源是否真正支持題目仍需人工核對。
